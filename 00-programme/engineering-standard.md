# Engineering standard

No project is complete until it has:

1. A clearly defined problem and requirements
2. Relevant textbook chapters and concepts identified
3. Architecture and design (schema, endpoints, structure)
4. Working implementation that you can explain line by line
5. Appropriate database and API design
6. Security considerations noted
7. Automated tests appropriate to its complexity
8. README, API documentation and GitHub repository
9. Screenshots or a short demonstration
10. Deployment where appropriate
11. A short explanation of the engineering decisions made

## Seven engineering dimensions

- **Web foundations:** HTTP, URIs, requests, responses and REST.
- **Programming:** JavaScript, TypeScript, React and Node.js.
- **Data engineering:** SQL, NoSQL, transactions, caching and data modelling.
- **Security:** Authentication, authorization, validation and secure coding.
- **Architecture:** Design patterns, modularity, scalability and distributed systems.
- **Quality engineering:** Testing, performance, monitoring and reliability.
- **Deployment:** Git, Linux, Docker, Kubernetes and CI/CD.

## Technology stack

- **Programming:** JavaScript, TypeScript
- **Frontend:** HTML, CSS, React
- **Backend:** Node.js, Express.js
- **API:** REST, OpenAPI
- **Relational database:** PostgreSQL

- **Caching:** Redis
- **Messaging:** RabbitMQ, Kafka
- **Testing:** Jest, Supertest, Playwright
- **Version control:** Git, GitHub
- **Operating system:** Linux
- **Containers:** Docker
